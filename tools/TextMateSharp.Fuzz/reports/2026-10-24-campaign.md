# Differential fuzzing campaign, 2026-10-24

TextMateSharp with GregsEx 0.4.3 (this fork's perf branch) against the official TextMateSharp 2.0.4 (Onigwrap 1.0.11),
over the 76 grammars bundled in `TextMateSharp.Grammars`. Fuzzer: `tools/TextMateSharp.Fuzz`.

## Campaign

| | |
|---|---|
| Machine | devbox1 (16 cores, 15 workers) |
| Duration | 2 h 17 min of fuzzing (seed 20261024) |
| Executions | 2,475,156 inputs, each tokenized line by line with `TokenizeLine` and `TokenizeLine2` by both versions |
| Discrepancies | 30,560, grouped into 207 unique findings |
| Verified with | GregsEx 0.4.3: every finding re-run with `repro` |

## Findings by source

### GregsEx

No open issue. The branch neither hangs, nor times out, nor throws where the official version does not.

One intended deviation from native Oniguruma:

| Issue | Findings | Note |
|---|---:|---|
| Native Oniguruma 6.9.10 over UTF-16 underflows in a nested negated class holding U+0000, so Ruby's `[[a-zA-Z0-9,. \t?!-][^\x{00}-\x{7F}]]*` matches any character | 2 (`source.ruby`: `/ # '` is a comment for official, regex text for the branch) | GregsEx computes the true complement, as vscode-oniguruma does with UTF-8. The branch agrees with VS Code; official does not. |

### Official TextMateSharp / Onigwrap

| Issue | Findings | Grammars |
|---|---:|---:|
| Hangs: one tokenization takes more than 60 s (a single native search cannot be interrupted by TextMateSharp's time limit); the branch takes 0.2-2.3 s on the same inputs | 5 | `source.cpp`, `source.cs`, `source.ts`, `text.html.cshtml`, `text.html.derivative` |
| Times out (5 s per line) where the branch does not, mostly lines of 1-5 k characters (quadratic tokenization) | 118 | 63 |
| Wrong tokens when Oniguruma's retry limit stops a search: from offset 0 the regex returns no match, from a later offset it finds the match the branch reports | 3 | `source.perl.6` |
| Lone surrogates: Onigwrap converts lines to UTF-8, so token offsets run past the line or tokens are lost | 72 | 72 |

The hangs are denial-of-service candidates in the official version: `TokenizeLine`'s time limit is only checked between
regex searches.

### TextMateSharp, both versions

| Issue | Findings | Note |
|---|---:|---|
| A back-reference pastes a captured lone surrogate into an end pattern (`(\G(?<!\uD800 [^\w-]))\|\}\|$` in Pug, `\uD83D` in Perl); both engines reject the pattern and throw | 5 (Pug, Ruby, Perl) | Same behavior in both; which side throws first depends on the rules earlier inputs compiled. |

## Not found

No differences in `TokenizeLine2` metadata, no grammar that loads in one version only, and no process crash.
